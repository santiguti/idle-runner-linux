# Idle Runner v2 (Windows + new UI + pending fixes) Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking. Dispatch each task's implementer with the **Model** line of that task (Agent tool `model` + `effort`; Santi asked for per-task models on 2026-10-26).

**Goal:** Turn the Linux-only bot into a findable, professional project that runs on Linux and Windows (with a Windows `.exe`), give it a polished and understandable window with an editable Ascension Tree buy order, then work through the pending bot fixes.

**Architecture:** The bot core already talks to the screen through one `Backend` protocol (`idle_runner/game.py`). Windows support is a second backend (`idle_runner/win32.py`, stdlib `ctypes`) chosen at runtime; nothing above `Game` changes. Process plumbing that used POSIX signals (stop, child processes) moves to stdin-EOF and a self-command that also works inside a PyInstaller build. The window is rewritten as a small `idle_runner/ui/` package on stdlib tkinter/ttk with its own dark theme; it reads the bot's state from `logs/events.jsonl`, which the bot already writes.

**Tech Stack:** Python ≥ 3.12, numpy, python-xlib (Linux only), stdlib `ctypes`/`tkinter`/`urllib`, pytest; build-only: PyInstaller + Pillow; GitHub Actions.

**Spec:** Santi's request of 2026-10-26 (below) + `docs/next-steps.md` (pending list, measured facts) + `CLAUDE.md` (rules).

### Task 4: Windows backend

**Files:**
- Create: `idle_runner/win32.py`, `tests/test_win32.py`

**Interfaces:**
- Consumes: `game.Backend`, `game.GameUnavailable`, `game.WindowGone`, `game.HELD_KEYS`.
- Produces:
  - `enable_dpi_awareness() -> None` — `user32.SetProcessDpiAwarenessContext(c_void_p(-4))` (per-monitor v2), falling back to `shcore.SetProcessDpiAwareness(2)`; errors ignored (already set). Also used by the UI before creating `Tk()`.
  - `class Win32Backend` with exactly the `X11Backend` surface: `__init__(window_name: str)`, `window_id: int`, `find_window()`, `size()`, `origin()`, `is_active()`, `grab(x, y, w, h) -> np.ndarray` (RGB, h×w×3), `move(x, y)`, `button(button: int, down: bool)`, `key(name: str, down: bool)`, `now_ms()`, `sleep_ms(ms)`.
  - Module-level, importable on Linux (for tests): `VK: dict[str, tuple[int, bool]] = {"Up": (0x26, True), "Right": (0x27, True), "a": (0x41, False), "d": (0x44, False), "r": (0x52, False)}` (bool = extended key); ctypes structures `MOUSEINPUT`, `KEYBDINPUT`, `HARDWAREINPUT`, `INPUT` (union); `bgra_to_rgb(data: bytes, w: int, h: int) -> np.ndarray`; `wheel_delta(button: int) -> int` (4 → +120, 5 → −120, else 0); `_load_dlls() -> tuple[user32, gdi32]` (`ctypes.WinDLL(..., use_last_error=True)`, monkeypatched in tests).

Decisions the implementer can't infer:
- Declare `argtypes`/`restype` for every function used; handles (`HWND`, `HDC`, `HBITMAP`) are pointer-sized (`c_void_p`/`wintypes.HANDLE`). The default `int` restype truncates 64-bit handles.
- `__init__` calls `enable_dpi_awareness()` before anything else.
- Window: `FindWindowW(None, name)`; 0 → `GameUnavailable("no window named …; is the game running?")`. Every call first checks `IsWindow(hwnd)` → `WindowGone`; `IsIconic` → `GameUnavailable("minimized")`.
- `size`: `GetClientRect`; `origin`: `ClientToScreen` of (0, 0); `is_active`: `GetForegroundWindow() == hwnd`.
- `grab`: copy from the **screen** DC (`GetDC(None)`) at origin + (x, y) with `BitBlt(…, SRCCOPY)` into a compatible bitmap, read with `GetDIBits` as 32-bit `BI_RGB` with **negative** `biHeight` (top-down); release DC/bitmap/memory DC in `finally`. The window DC of a DirectX/Unity window can come back black; the screen DC is what AutoIt's `PixelGetColor` used. Consequence (document in the docstring): anything on top of the game is captured too — fine, the bot only acts while the game is the foreground window.
- `move`: `SetCursorPos(origin + (x, y))`. `button`: 1 → `SendInput` `MOUSEEVENTF_LEFTDOWN`/`LEFTUP`; 4/5 down → `MOUSEEVENTF_WHEEL` with `wheel_delta`, up → nothing. `key`: `SendInput` keyboard input with `wVk`, `wScan = MapVirtualKeyW(vk, 0)`, `KEYEVENTF_EXTENDEDKEY` for arrows, `KEYEVENTF_KEYUP` on release; unknown name → `ValueError` like X11.
- Hold a `threading.RLock` around every call (the jumper thread and the main loop both send input), as `X11Backend` does.
